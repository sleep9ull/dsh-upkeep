# Upkeep

Upkeep 是 DeepSeek Harness 的插件兼容性管家。它回答一个问题：**我写的这些 DSH 插件，还能不能在当前（以及即将到来的）DSH 上正常工作？**

## 它做什么

- **一级侧栏面板**：在左侧面板列表里与 Plugins、Automation tasks 同级，有一个固定的 Upkeep 图标；点开是整页的状态总览。
- **Plugins 设置页分页**：同一个视图的二级入口，页头可直接跳到一级面板。
- **监测范围**只包含第三方插件；官方 `@deepseek-ai/*` 包属于 DSH 本身、随 DSH 版本发布，不纳入监测，面板会说明排除了多少 bundle 与插件条目。
- **归属与维护**：每个插件给出 `我的 / 他人 / 未知` 的归属判定（依据包 scope、author、repository、本地 checkout 的 git remote，匹配本地身份），只有"我的"插件才计算是否需要维护；判定依据在悬停时可见，识别不出时显示未知而不是猜测。
- 「定时检查」会创建一个周期性的 DSH 任务，每次投递执行检查并汇报，不会自行修改仓库；任务在 Automation tasks 页面管理。
- 验证通过后可以「创建 PR」（提交 + 推送 + gh 建 PR）；若开启 allowMerge，还可对已创建的 PR 执行「合并」，两步都需要确认。
- 属于你的插件需要维护时，行上会出现「升级」按钮：确认后（可选 worktree）会在新会话里打开一段针对命中的迁移条目生成的提示词；改完回到面板点「验证」逐条跑验证命令。
- 检查时会用 DSH 的升级指南匹配插件实际使用的接口，命中数量显示在行的悬停提示里；agent 可通过 upkeep_status 的 report.get 取到完整迁移条目。
- 顶部元信息显示运行中的 DSH 版本与目标 DSH 版本（含发布通道与缓存标记）；「立即检查」会刷新目标版本、重新判定并把报告写入本地状态。
- 面板先给出一句结论（插件全部正常 / 有 N 个需要维护 / 尚未识别），再用台账列出每个插件的版本、状态与维护结论；列表按归属分成「我的插件」与「其他插件」两组，**「其他插件」默认折叠**，点标题展开。
- 提供 `upkeep_status` 工具，让会话内的 agent 也能读取同一份状态（一个操作，两个调用方：面板与工具共用同一个 dispatcher）。

## 怎么用

1. 点击左侧面板列表里的 **Upkeep** 图标，打开状态总览。
2. 点 **刷新** 读取最新状态。
3. 也可以从 **设置 → Plugins → Upkeep** 打开同一个视图。
4. 需要 agent 参与时，在会话里让它调用 `upkeep_status`。

## 当前范围与限制

- 本版本只做**只读状态总览**，不做兼容判定、不改任何文件、不发起网络请求。
- 兼容性判定、迁移报告、一键升级、PR/合并与定时任务在后续里程碑实现（见仓库 `docs/PLAN.md`）。
- 面板数据来自 Host 半通过 `/api/upkeep/*` 提供的只读接口；没有开启客户端半时，工具仍可用。
