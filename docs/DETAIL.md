# Upkeep

Upkeep 是 DeepSeek Harness 的插件兼容性管家：它知道哪些已安装插件属于你，判断它们在当前与下一个 DSH 上还能不能工作，并把一次不兼容变成定向升级、验证与一个由你确认的 PR。

## 它做什么

- **兼容性监测**：从 npm registry 获取目标 DSH 版本（通道感知、不迷信 `latest`），对运行版与目标版分别做声明层判定，并合并实时插件行状态。新版本会弄坏哪个插件，在升级前就看得见。
- **迁移报告**：读取 DSH 自带的升级指南，扫描插件真正使用的接口（包、服务、事件、工具、命令、slot、patch 行、config key），只列出命中这些面的破坏性变更，并附 Change / Migration 原文与命中依据。
- **一键定向升级**：用命中的变更生成有边界的提示词，可选在独立 git worktree 中执行，并打开一个会话；agent 修改后可在面板点「验证」运行插件自己的检查与测试。
- **范围边界**：升级只针对 DSH 版本变化引发的兼容问题。过程中发现的其它问题（代码缺陷、测试失败、依赖过旧等）不会被修改；会话结尾按 P0 / P1 / P2 列出这些问题本身，不给修法、不估工、也不碰相关代码。
- **人工确认的交付**：验证通过后可提交、推送并创建 PR；开启 `allowMerge` 后还能合并，每一步都需要确认。
- **定时巡检**：通过 DSH 的定时任务周期性检查并汇报，不会自行修改仓库。任务里保存的只是「启动器」，具体策略由当前插件版本提供，因此升级插件后老任务会自动采用新策略（你自己改写过的提示词不会被覆盖）。
- **归属判定**：基于包 scope、author、repository、本地 checkout 与 git remote，与本机身份（配置、`~/.gitconfig`、gh 登录）匹配，给出我的 / 他人 / 未知；官方 `@deepseek-ai/*` 包排除并计数。

## 怎么用

1. 点击左侧面板列表里的 **Upkeep** 图标（或 **设置 → Plugins → Upkeep**）。
2. 点 **刷新** 重新读取并判定全部插件（目标版本在 `feedTtlMinutes` 内复用缓存），同时产出一份报告；行悬停可看兼容性需求、归属证据与命中的迁移条目。
3. 对需要维护的自己的插件点 **升级**，确认（可选 worktree）后会带着提示词打开会话。
4. 改完点 **验证**；通过后可 **创建 PR**，开启 `allowMerge` 时还可 **合并**。
5. 想让某个插件周期性被检查，就在它行的「定时」单元格点 **创建**，在弹出的对话框里选一个每天的时间（默认 08:00，按本机时区）；一次只为一个插件创建；创建后该格显示触发频率，任务本身在 DSH 的 Automation tasks 页面管理。
6. agent 也能用 `upkeep_status` 工具读取同一份数据，并通过 `report.get` 取完整迁移条目。

## 范围与限制

- 只在 DSH `0.2.2-rc.3` 上验证；声明范围 `>=0.2.2-rc.3 <0.3.0`（未测试的 prerelease 不再声明）。
- PR 需要宿主 `gh` CLI 已登录；合并默认关闭（`allowMerge: false`），且每次都要确认。
- 未发布到 npm，需从本地 checkout 安装；link 安装直接服务 `dist/`，Host 改动后需重启。
- 远端指南与目标版本读取需要网络；失败时降级到安装版指南/缓存并给出提示，不会假装完整。
- 状态保存在 `$DSH_HOME/upkeep/state.json`，是有界、可再生的派生数据。
